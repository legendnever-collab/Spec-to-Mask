# Security Policy

## Supported code

Security maintenance focuses on the current `main` branch. Historical game releases, demonstration archives, and screenshots are kept as reference material.

## Reporting a vulnerability

Do **not** disclose vulnerabilities, credentials, tokens, proprietary documents, or exploitable details in a public Issue, Discussion, or Pull Request.

If the repository's **Security → Report a vulnerability** feature is enabled, use that private reporting channel. If it is unavailable, contact the maintainer through an existing private channel before sharing details. Public GitHub Issues are **not private**.

Please include a concise description, affected version, reproduction steps, and security impact. Never submit real secrets or personal data as test evidence.

## Contributor precautions

- Use pull requests and review CI results before merging.
- Do not commit `.env`, API tokens, credentials, SSH keys, internal work documents, or confidential partner information.
- Treat forked pull requests and third-party GitHub Actions as untrusted until reviewed.
- Dependency update pull requests are recommendations, not automatic approvals. Test before merging.

This policy does not grant permission to access systems or data without authorization.
