# SPEC-to-MASK v2 — P0 UX Review Prototype

**UX MOCK — NOT PHYSICS VERIFIED. P0 only. No production game state is read or written.**

Open [`index.html`](index.html) directly in a browser. It is self-contained and runs offline; GitHub's code viewer shows its source, so download the raw file first. URL fragments are not required. Optional query examples: `index.html?scene=wg` and `index.html?scene=mzm`.

## Review in this order

1. **Engine:** whole optical chain,8 planned lanes, current Tutorial, one Start action. Uncomputed system metrics say “Not evaluated”.
2. **Waveguide:** move Bend Radius; geometry/area and marker change; optical bend loss says “Not evaluated” because no solver is connected to this mock.
3. **MZM:** change length; normalized voltage requirement falls and active-loss ratio rises; ideal interference redistributes the two outputs. Switch Discover→Engineer without replacing the canvas.
4. Try Capture comparison → edit → Restore comparison → Original. Open Learn Physics and Close/Escape; values and revision are unchanged. Switch theme and compare phone layouts.

Discover Continue/Skip is nonblocking. Continuing without manipulation does not award the fixture's observed-completion flag. Mock mode has no scores or production progression. All state is memory-only and resets on reload. The scene selector is for reviewers and is not a proposed game menu.

## Numerical truthfulness

- Waveguide footprint ratio is the fixed-width isolated quarter bend's occupied square `(R+w/2)^2`, normalized atR₀=8µm, w=.45µm; no leads/clearance.
- `KINDS.wg` has no bend model. **Existing `LAB.routeLoss` does have a strip/EIM arc-loss path**, recommended for reviewed P1 reuse. It is intentionally not integrated in this P0 prototype.
- MZM ratios are illustrative `Vπ/Vπ₀=L₀/L`, `active loss/loss₀=L/L₀`, L₀=2mm. Active loss omits passive offsets and is not total IL. Absolute volts/dB/BER are not claimed.
- MZI uses a fixed normalized test drive and quadrature bias; output fractions are of surviving power. It is an ideal schematic, not a field simulation or existing-engine result.
- Engineer targets are dimensionless UI fixtures; no engineering PASS or real driver specification is awarded.

Actual baseline engine outputs for width, Lab arc losses and MZM length are in [`source-audit.json`](source-audit.json), generated by `node prototypes/v2-p0/audit-source.cjs`. They are separate from the mock and do not claim external validation.

## Reproduce UI checks

From repository root, use the existing `npm ci` development dependencies and installed Playwright Chromium:

```sh
npx playwright install chromium
node prototypes/v2-p0/check.cjs
```

If Chromium is already available, set `SMQ_BROWSER=/absolute/path/to/chromium`. The local restricted environment used cached Chromium153.0.8010.0 with GPU disabled. CI uses Playwright's bundled Chromium; exact rasterization may differ. Assertions use element bounds and state semantics, not pixel snapshots.

Evidence: [`verification.json`](verification.json), [`QA.md`](QA.md), [`screenshots/`](screenshots/), [`SHA256SUMS`](SHA256SUMS).4 sizes ×3 scenes ×2 themes, plus Engineer/Learn and changed-parameter views. No claims about real learners, calibrated optics or production adapter races.
